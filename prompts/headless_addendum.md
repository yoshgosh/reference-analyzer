# 無人実行時の追加ルール（上位規則）

本節は前掲の指示文に対する差分であり，**矛盾する場合は本節を優先する**．

## 1. 対象の限定（最重要）

- 処理対象は，末尾の「今回の対象」に示された**資料1本のみ**である．
- 次の情報は一切使用しない．
    - 他の資料，他の実行，過去の会話の内容
    - 記憶・メモリに残る論文情報
    - 作業ディレクトリ外のファイル
- 作業ディレクトリ内に**対象以外の資料**（別の論文PDF等）が存在した場合は，それを無視し，その事実を `error` に記録する．自分が作成した一時ファイルはこれに該当しないので報告しなくてよい．
- 判断に迷った場合は，推測で補わず空欄にする．

## 2. Web検索で得た情報の扱い

- Web検索・Web取得は，**対象と同一の資料**を確認する目的にのみ使う．
- 取得した情報が対象と同一の資料のものであることを，**タイトル・著者・DOI の一致**によって確認する．一致を確認できない情報は使用しない．
- 類似題目・同一著者の別論文・サーベイ等の情報を，対象の記述に混ぜてはならない．

## 3. 無人実行であること

- ユーザーは不在である．**質問をしてはならない．** 確認を求めて停止してはならない．
- 承認が必要な事項（新規タグの追加等）は，前掲の指示文に従って自律的に判断する．
- 判断できない項目は空欄（空文字列）とする．

## 4. ファイル操作の制限

- 一時ファイルは**カレントディレクトリ（作業ディレクトリ）内にのみ**作成する．
- **対象ファイルの改名・移動・削除をしてはならない．** 改名はスクリプトが行う．
- 作業ディレクトリ外への書き込みをしてはならない．

## 4.1 コマンド実行の制約（重要）

実行できるコマンドは次に限られる．これ以外のコマンドは拒否される．

```
pdftotext  pdfimages  pdftoppm  pdfinfo  curl
```

- **1回の呼び出しで実行するコマンドは1つだけにする．** `;` で複数のコマンドを連結すると，
  全体が拒否される（例：`ls -la; pdfinfo x.pdf` は失敗する）．必要なら呼び出しを分ける．
- パイプ（`|`）は使用できる（例：`pdftotext x.pdf - | head -20`）．
- **あるコマンドが拒否されても，コマンドの実行そのものが禁じられたと判断してはならない．**
  上の一覧にある別のコマンドで目的を達せられることが多い．特に代表画像の取得を，
  1度の拒否で諦めてはならない．

## 5. Citation Key

- **ASCII の英数字のみ**で構成する（記号・空白・非ASCII文字を含めない）．
- 日本語の著者名・組織名はローマ字化する（例：山田太郎 → Yamada）．
- 年が不明な場合は `nd` を用いる（`n.d.` の記号は Citation Key には使わない．BibTeX 内の表記は前掲の指示文に従う）．

## 6. Notion 操作

- Notion の操作には `mcp__notion__*` のツールを用いる．
- 登録先は `{{NOTION_DATA_SOURCE_ID}}` である．

### 代表画像のアップロード手順

0. 画像の取得は次の順に試す．
   - 公式サイト（arXiv HTML版・出版社サイト等）から元画像を `curl` で取得する．
   - 取得できない場合は PDF から抽出する．`pdfimages -list` で図の所在を調べ，
     `pdfimages -png -f <頁> -l <頁>` で抽出する．図が複数の要素に分かれていて
     うまく取れない場合は，`pdftoppm -png -r 150 -f <頁> -l <頁>` で該当ページ全体を
     画像化してもよい．
1. `mcp__notion__notion-create-file-upload` を呼び，アップロード先の情報を得る．
2. 返却されたアップロード先へ `curl` で画像を送信する．
3. アップロードしたファイルを参照する画像ブロックを，**ページ本文の先頭**に置く．
4. キャプションに日本語の説明を記載する．

- いずれかの段階で失敗した場合は，**画像なしで登録を続行**し，失敗した理由を `image_status` に記録する．画像の失敗は全体の失敗としない．
- 成功した場合も `image_status` に結果を記載する．

## 7. 最終出力（前掲「ステップ4: 完了報告」の置き換え）

前掲の指示文のステップ4（ユーザーへの完了報告）は行わない．代わりに，構造化出力として次のJSONを返す．

| キー | 内容 |
|---|---|
| `status` | Notion への登録まで完了した場合のみ `success`．それ以外は `failed` |
| `citation_key` | 登録した Citation Key（ASCII 英数字のみ） |
| `title` | 原文タイトル |
| `notion_url` | 作成した Notion ページのURL |
| `rating` | 評価（`★` / `★★` / `★★★`） |
| `rating_reason` | 評価の理由 |
| `image_status` | 代表画像の結果（成功時はその旨，失敗時は理由） |
| `error` | 失敗理由．成功時は空文字列 |

- 該当しない項目は**空文字列**とする（キー自体を省略してはならない）．
- **ページを作成した後に失敗した場合も，`notion_url` を必ず記録する**（手動補修のため）．
- `status` が `failed` の場合は，`error` に失敗した段階と理由を具体的に記載する．
