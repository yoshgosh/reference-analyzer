# 無人実行時の追加ルール（上位規則）

本節は前掲の指示文に対する差分であり，**矛盾する場合は本節を優先する**．

## 1. 対象の扱い（無人実行での補足）

- 「今回の対象」は末尾に示す．作業ディレクトリ外のファイルは使用しない．
- 「今回の対象」「補助資料」のどちらにも列挙されていないファイルは無視する．
  自分が作成した一時ファイルについては報告しなくてよい．
- 補助資料を別の文献だと判断して使わなかった場合は，どれをなぜ使わなかったかを
  `error` に記録する（`status` は `success` のままでよい）．

## 2. 無人実行であること

- ユーザーは不在である．**質問をしてはならない．** 確認を求めて停止してはならない．
- 承認が必要な事項（新規タグの追加等）は，前掲の指示文に従って自律的に判断する．
- 判断できない項目は空欄（空文字列）とする．

## 3. ファイル操作の制限

- 一時ファイルは**カレントディレクトリ（作業ディレクトリ）内にのみ**作成する．
- **対象ファイルの改名・移動・削除をしてはならない．** 改名はスクリプトが行う．
- 作業ディレクトリ外への書き込みをしてはならない．

## 4. コマンド実行の制約（重要）

実行できるコマンドは次に限られる．これ以外のコマンドは拒否される．

```
{{ALLOWED_COMMANDS}}
```

- **1回の呼び出しで実行するコマンドは1つだけにする．** `;` で複数のコマンドを連結すると，
  全体が拒否される（例：`ls -la; pdfinfo x.pdf` は失敗する）．必要なら呼び出しを分ける．
- パイプ（`|`）は使用できる（例：`pdftotext x.pdf - | head -20`）．
- **あるコマンドが拒否されても，コマンドの実行そのものが禁じられたと判断してはならない．**
  上の一覧にある別のコマンドで目的を達せられることが多い．特に代表画像の取得を，
  1度の拒否で諦めてはならない．

## 5. 代表画像

1. 画像を次の優先順位で取得する．**対象そのものから取れるものを優先する．**
   1. **PDF から抽出する．** 「今回の対象」の下調べの結果（`pdfimages -list` と本文テキスト）から
      図の頁と寸法を調べ，`pdfimages -png -f <頁> -l <頁>` で抽出する．
   2. 図がベクタで描かれていて `pdfimages` では取れない場合，または断片しか取れない場合は，
      公式サイト（arXiv HTML版等）から元画像を `curl` で取得する．
      取得した画像が**対象と同一の資料のものである**ことを確認する（「Web検索で得た情報の扱い」）．
   3. それも取れない場合は `pdftoppm` でページを画像化する．
      低解像度（`-r 80`）で図の位置を確認し，`-r 150` と `-x -y -W -H` で図の範囲を切り出す．
      **ページ全体を代表画像にはしない**（本文が写り込む）．

   対象が URL の場合は PDF が無いので，1 と 3 は使えない．2 のみを行う．
2. 選んだ画像を作業ディレクトリに置いたまま，そのパスを `image_file` に書く
   （例：`fig-05.png`）．形式は PNG・JPEG・GIF・WebP のいずれかで，20MB 以下とする．
3. `image_caption` に日本語の説明を書く（図表番号・出典があれば含める）．

- アップロードと本文への挿入はスクリプトが行う．
- **図表が存在するのに画像を取得できなかった場合は `status` を `failed` とする**（§6）．
- 対象に図表・画像がそもそも存在しない場合は，`image_file` を空にして `success` としてよい．

## 6. 最終出力

ユーザーへの報告は行わない．構造化出力として次のJSONを返す．
Notion への登録は，この出力を使ってスクリプトが行う．

| キー | 内容 |
|---|---|
| `status` | `success` または `failed`（下記の基準） |
| `error` | 失敗した段階と理由．成功時は空文字列 |
| `citation_key` | Citation Key（ASCII 英数字のみ） |
| `title` | 原文タイトル |
| `doi` | DOIリンク（または公開URL） |
| `summary` | 概要（一段落） |
| `tags` | 選んだタグの配列（新しいタグも含める） |
| `new_tags` | 新しく作るタグの配列．各要素は `{"name": …, "color": …}`．無ければ空配列 |
| `author` | 著者（所属）・公開者 |
| `year` | 出版年・公開年（西暦4桁の文字列．例：`"2024"`） |
| `publication` | 掲載先・公開元 |
| `citation` | BibTeX |
| `rating` | `★` / `★★` / `★★★` |
| `body` | 要約の本文（Markdown．「要約の作成」の形式に従う．画像は含めない） |
| `image_file` | 代表画像のパス（作業ディレクトリからの相対パス）．画像が無ければ空 |
| `image_caption` | 代表画像のキャプション．画像が無ければ空 |

各項目の内容と形式は「書誌情報の抽出」「要約の作成」の定義に従う．

### status の基準

`success` とするのは，次の**両方**を満たす場合のみである．

1. 書誌情報と要約を作成できた．
2. 代表画像を取得できた．
   **ただし対象に図表・画像がそもそも存在しない場合は，画像なしで `success` としてよい．**

次の場合は `failed` とする．

- 対象を読めなかった，または書誌情報・要約を作成できなかった．
- **図表・画像が存在するのに，取得に失敗した．**
  代表画像は要約の一部であり，入っていない登録を完了とはみなさない．

`failed` の場合も，作成できた項目は埋めて返す（調査に使う）．

### その他

- 該当しない項目は**空文字列**とする（キー自体を省略してはならない）．
- `error` には失敗した段階と理由を**簡潔に**記載する．
  段階は**名前で書く**（「書誌情報の抽出」等）．**番号は使わない**
  （通知にはパイプラインのステップ番号が別に並ぶため，混ざる）．
  画像が原因の場合は，図表が存在することと，どの方法で取得を試みて失敗したかを書く．
- 対象に図表が存在せず画像なしで `success` とした場合は，`error` は空にする．
